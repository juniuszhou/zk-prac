# Hardhat Deployment For The Addition Proof

This project deploys the Circom `a + b = c` verifier to Polkadot-compatible Solidity environments.

It contains two contracts:

- `Groth16Verifier`: generated by `snarkjs` from `circuits/addition.circom`.
- `AdditionProofApp`: a small wrapper that exposes `verifyAddition(publicSum, pA, pB, pC)`.

## EVM And PVM Deployment Targets

Polkadot Hub smart contracts support two execution formats:

- EVM / REVM: standard Ethereum bytecode and standard Hardhat deployment.
- PVM / PolkaVM: Solidity compiled through Parity `resolc` into PolkaVM-compatible artifacts.

For this Groth16 verifier, the key compatibility point is the BN254 precompile usage inside the generated verifier. The verifier calls Ethereum precompile addresses `0x06`, `0x07`, and `0x08` for elliptic curve addition, scalar multiplication, and pairing checks. This is the normal `snarkjs` verifier pattern for Groth16 on BN254.

Before using the PVM deployment in production, confirm that the target Polkadot Hub TestNet runtime supports those verifier precompile calls for PVM contracts. If not, the EVM / REVM deployment path is the safer target for this exact generated verifier.

## Install

This repository pins Hardhat 2.x because the local machine is on Node 20 and Hardhat 3 requires a newer Node version.

```bash
npm install
```

For PVM compilation with `@parity/hardhat-polkadot`, Polkadot docs recommend Node `22.5+`. If PVM compile fails on Node 20, upgrade Node and reinstall dependencies.

## Compile

Standard Hardhat compile:

```bash
npm run compile
```

This writes normal EVM artifacts to `artifacts/`.

PVM / PolkaVM compile:

```bash
npm run compile:pvm
```

This writes PolkaVM artifacts to `artifacts-pvm/` so they do not overwrite the EVM artifacts.

The Polkadot plugin is configured with:

```js
resolc: {
  compilerSource: "npm"
}
```

so `npm run compile:pvm` can produce Polkadot-compatible artifacts when the plugin and Node version are supported.

## Test Locally

The tests deploy the generated verifier and wrapper, then verify the sample proof generated from:

```json
{
  "a": "3",
  "b": "4",
  "c": "7"
}
```

Run:

```bash
npm test
```

The committed fixture files are:

- `test/fixtures/addition-proof.json`
- `test/fixtures/addition-public.json`

If you regenerate the Groth16 proving key, regenerate these fixtures too because proofs are tied to the verification key embedded in the generated `contracts/AdditionVerifier.sol`.

## Deploy To Polkadot Hub TestNet: EVM / REVM

Create `.env` from `.env.example` and set:

```bash
PRIVATE_KEY=0x...
```

Deploy with the normal EVM bytecode path:

```bash
npm run deploy:polkadot:evm
```

The configured Polkadot Hub TestNet RPC is:

```text
https://services.polkadothub-rpc.com/testnet
```

with chain ID:

```text
420420417
```

## Deploy To Polkadot Hub TestNet: PVM / PolkaVM

The PVM path uses `@parity/hardhat-polkadot` and `@parity/resolc`.

Recommended environment:

```text
Node.js >= 22.5
npm >= 10.9
```

Deploy with Ignition:

```bash
npm run deploy:polkadot:pvm
```

PVM deployment uploads code and instantiates the contract under the hood. For simple standalone contracts like this verifier and wrapper, the toolchain should handle that process. Avoid factory-style runtime bytecode generation for PVM contracts.

## Verify A Sample Proof Against A Deployment

After deployment, set the wrapper address:

```bash
export ADDITION_APP_ADDRESS=0x...
```

Then call:

```bash
npx hardhat run scripts/verify-sample-proof.ts --network polkadotTestnet
```

Or call the same deployed wrapper with a standalone TypeScript viem client:

```bash
npm run call:verify:viem
```

You can also set the address inline:

```bash
ADDITION_APP_ADDRESS=0x... npm run call:verify:viem
```

Expected Hardhat script result:

```text
Proof for public sum 7: valid
```

Expected viem script result:

```text
Proof valid: true
```
